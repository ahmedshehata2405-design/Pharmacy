# نظام إدارة الصيدلية (Pharmacy Management System)

نظام ويب لإدارة صيدلية متعددة الفروع: أدوية، مخزون، موردين، مشتريات، عملاء،
أطباء، وصفات طبية، ومبيعات — مبني بـ **ASP.NET Core MVC** بمعمارية 3 طبقات
(DataAccess / Business / Web).

## المتطلبات

- .NET 8 SDK (أو الإصدار المتوافق مع مشروعك)
- SQL Server (أي إصدار: Express كافي للتجربة)
- Visual Studio 2022 أو أي IDE يدعم C#

## هيكل المشروع

```
Pharmacy.sln
 ├── Pharmacy.DataAccess   (Class Library) - كل استعلامات SQL الخام
 ├── Pharmacy.Business     (Class Library) - منطق التطبيق والتحقق من صحة البيانات
 └── Pharmacy.Web          (ASP.NET Core MVC) - الكونترولرز والـ Views
```

## خطوات التشغيل

### 1. إنشاء قاعدة البيانات
شغّل الملفات دي بالترتيب على SQL Server (SSMS أو Azure Data Studio) — محتاج SQL Server 2016 SP1 أو أحدث:

1. `Database/PharmacyDB.sql` — بينشئ قاعدة `PharmacyDB` بكل الجداول والعلاقات، ومعاه **5 فروع** و**9 تصنيفات**.
2. `Database/02_TSQL_Logic.sql` — **إجباري**: بيضيف الـ constraints والـ indexes والـ stored procedures
   (`usp_CreateSale` و`usp_CreatePurchase`). شاشتَي المبيعات والمشتريات بيستدعوهم، فمن غيره الحفظ هيفشل.
   ممكن يتشغّل أكتر من مرة بأمان.
3. `Database/03_SeedData.sql` — بيانات تجريبية جاهزة: **37 دواء** موزعين على كل الفروع بكميات وأسعار وتواريخ صلاحية مختلفة
   (فيه أصناف قربت تخلص وأصناف قربت تنتهي عشان تنبيهات الداشبورد تشتغل)، موردين، عملاء، أطباء، ومستخدمين.
   ممكن يتشغّل أكتر من مرة بأمان (مبيضيفش حاجة موجودة). لو الداتا بيز عندك متعملة قبل كده بفرع واحد بس،
   شغّل `03_SeedData.sql` بس وهيضيف باقي الفروع والأدوية من غير ما يمسح حاجة.

### 2. ضبط الاتصال بقاعدة البيانات
افتح `Pharmacy.sln` في Visual Studio، وعدّل الـ Connection String في
`Pharmacy.Web/appsettings.json` (المفتاح `PharmacyDBConnectionString`) ليطابق
اسم السيرفر بتاعك (الافتراضي `.\SQLEXPRESS`).

### 3. المستخدمين
`03_SeedData.sql` بيضيف المستخدمين دول (كلمات المرور مشفّرة SHA256 بنفس صيغة `clsPasswordHasher`):

| المستخدم | كلمة المرور | الدور |
|---|---|---|
| `admin` | `Admin@123` | Admin (على الفرع الرئيسي) |
| `pharmacist1` ... `pharmacist5` | `Pharm@123` | Pharmacist (واحد لكل فرع، الرقم = كود الفرع) |
| `cashier1` ... `cashier5` | `Cash@123` | Cashier (واحد لكل فرع) |

النظام مفيهوش شاشة "تسجيل" عامة (عن قصد — دي صيدلية، مش موقع عام). ولو مش عايز بيانات تجريبية وعايز Admin بس:

```sql
INSERT INTO Users (Username, PasswordHash, Email, RoleID, BranchID, IsActive, CreatedDate)
VALUES ('admin', 'e86f78a8a3caf0b60d8e74e5942aa6d86dc150cd3c03338aef25b7d2d7e3acc7',
        'admin@pharmacy.com', 1, 1, 1, GETDATE());
```

⚠️ **غيّر كل كلمات المرور دي** (أو احذف الحسابات التجريبية وأضف حسابات بباسورد قوي) قبل تسليم النظام للعميل.

### 4. تشغيل المشروع
```
dotnet run --project Pharmacy.Web
```
أو من Visual Studio: اجعل `Pharmacy.Web` هو Startup Project واضغط Run.

سجّل دخول بـ `admin` وجرّب: القايمة العلوية فيها كل الشاشات، ومن **الإعدادات** تقدر تدير الفروع والتصنيفات.

## الصلاحيات (Roles)

| الدور | الصلاحيات |
|---|---|
| **Admin** | كل شيء، بما فيه الحذف وإدارة الفروع |
| **Pharmacist** | إضافة/تعديل الأدوية والتصنيفات، المخزون، المشتريات، الوصفات، المبيعات (بدون حذف) |
| **Cashier** | البيع، وتسجيل الوصفات والعملاء والأطباء (إضافة فقط) أثناء البيع، وعرض الشاشات الأساسية |

## نقاط مهمة قبل الاستخدام الفعلي (Production Checklist)

- [ ] **غيّر الباسورد الافتراضي** لأي مستخدم Admin تجريبي
- [ ] **استخدم HTTPS** في البيئة الفعلية (مفعّل بالفعل في `Program.cs` عبر `UseHttpsRedirection`)
- [ ] **راجع الـ Connection String** — متسبهوش فيه باسورد SQL Server ظاهر في كود متسجل على Git العام
- [ ] **اعمل نسخة احتياطية دورية** لقاعدة البيانات (`PharmacyDB`)
- [ ] فاتورتَي البيع والشراء بيتحفظوا عن طريق **stored procedures** (`usp_CreateSale`, `usp_CreatePurchase`)
      جوه Transaction واحدة (الفاتورة + البنود + تحديث المخزون). أي خطأ = Rollback كامل.
      قواعد البيع كلها في الداتا بيز: الدواء اللي محتاج وصفة، توفر الكمية في مخزون الفرع،
      **الدواء منتهي الصلاحية مش بيتباع**، والسعر بيتاخد دايمًا من المخزون
- [ ] الداتا بيز نفسها بتمنع: تكرار (فرع + دواء) في المخزون، والكمية السالبة، والأسعار السالبة
- [ ] راجع صلاحيات كل Role حسب احتياج العميل الفعلي — دلوقتي هي افتراض بسيط
      (Admin/Pharmacist/Cashier) ممكن تحتاج تفصيل أكتر

## الموديولات الموجودة

- ✅ المصادقة والصلاحيات (Cookie Authentication)
- ✅ الأدوية (Medicines)
- ✅ الفروع (Branches) — شاشة إدارة كاملة للـ Admin (إضافة/تعديل/حذف؛ الحذف بيترفض لو الفرع عليه بيانات)
- ✅ التصنيفات (Categories) — شاشة إدارة، وبتعرض عدد الأدوية في كل تصنيف
- ✅ المخزون (Inventory) — مع تنبيهات قرب انتهاء الصلاحية والكمية المنخفضة
- ✅ الموردين (Suppliers) + المشتريات (Purchases)
- ✅ العملاء (Customers) + الأطباء (Doctors)
- ✅ الوصفات الطبية (Prescriptions)
- ✅ المبيعات (Sales) — اختيار الفرع بيعرض أدويته المتاحة بالسعر والكمية، إجمالي لحظي، تنبيه للأدوية اللي محتاجة وصفة،
  إضافة عميل جديد من نفس الشاشة، وبعد البيع بتفتح فاتورة جاهزة للطباعة
- ✅ لوحة تحكم رئيسية (Dashboard) بإحصائيات سريعة
